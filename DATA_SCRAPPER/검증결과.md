# 검증 결과

- 기존 네이버 프로젝트 원본은 수정하지 않고 `NaverKboRelayUI` 별도 프로젝트를 생성했습니다.
- .NET 8 WinForms Release 빌드 및 테스트 실행.
- 실제 공개 응답: 2026-09-11 네이버 일정 조회 HTTP 200, 6개 일정 중 KBO 4경기 필터 확인. 해당 경기 네이버 기본/1회 API 응답도 HTTP 200 확인.
- KBO 직접 POST로 받은 실제 문자중계/점수판 HTML을 C# 파서에 입력하여 로그 496개, 타자 24명, 투수 8명, 최종 4:6 확인.
- 사용자 네이버 전체중계 JSON으로 선수 식별 32행 연결 확인. 같은 팀 타자/투수 김태훈 두 명을 65040/62360으로 구분했습니다.
- 네이버 점수·통계·타석결과·타순·배열 순서를 고의로 변경해도 KBO 기록값과 ID 연결이 변하지 않는 것을 확인했습니다.
- 이름/ID 중복, 동명이인, 잘못된 경기/팀, 상충 식별정보는 미확정 또는 오류로 처리했습니다.
- HTTP 모의 응답을 사용해 날짜별 일정 페이지 처리, 기본 응답 후 1~9회 총 10요청, 원본 93개 네이버 중계 그룹 보존, 이닝 누락/실패/다른경기/다른이닝/중복·경기 진행중·단축경기·취소 처리를 확인했습니다.
- 통합 수집 모의 테스트: KBO 실패 후 KBO만 재시도, 네이버 일부 이닝 실패 후 네이버만 재시도, 완료 파일 건너뛰기, 공식기록 불변, 취소 시 기존 파일 보존, 정규시즌 외 제외, ID 연결 구조 오류 시 네이버 재수집.

## 검증하지 못한 부분

이 작업 실행 환경에서는 C# HttpClient의 Windows Schannel TLS 연결이 SEC_E_NO_CREDENTIALS(0x8009030E)로 실패했습니다. Node.js를 이용한 실제 공개 HTTP 요청은 성공했지만 C# 실행 파일에서 서버 요청부터 저장까지의 실제 종단간 성공은 미검증입니다. 인증서 검증을 비활성화하지 않았습니다. 실제 GUI 버튼 클릭 검증도 수행하지 않았습니다.

테스트를 재현하려면 소스 ZIP의 `NaverKboRelayUI.Tests/Test.ps1`을 실행하세요. 테스트 자체의 네트워크는 모의 응답을 사용하며 빌드 시 패키지 복원에는 인터넷이 필요할 수 있습니다. 테스트 샘플은 함께 포함했습니다. 우선 하루를 선택해 실행하면 로그에서 실제 환경의 통신 성공 여부를 확인할 수 있습니다.
