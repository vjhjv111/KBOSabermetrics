## 실행한 검사

- `WEB/diamond-game`: `npm test`, `npm run typecheck`, `npm run build` 통과. 전체 경기 최초 통합 검증 번들은 `game-G5JBEHOD.js`, `game-M3D4QSEG.css`였다. 저장 코드 추가 후 검증은 아래 별도 항목에 기록했다.
- .NET 웹 앱 빌드: 경고 0, 오류 0. 기존 DiamondGame/Roster/Pitching 검증 프로젝트도 Release 빌드 성공.
- [기존 DiamondGame 회귀](../validation/DiamondGame/README.md)를 실제 실행해 총 42,373개 검사를 통과했다. 최신 TypeScript 엔진으로 생성한 108개 투구·756개 판정을 C# 엔진과 비교한 수치·형태 검사 42,319개를 포함한다. 몸 충돌 17개 투구와 사구 34개 판정, 양쪽 AI 시점, 6타석 PvP 종료, 동시 참가·소유권·중복 득점 방지·입력 시각·재시작·만료·생성 제한, HTTP CSRF·쿠키·출처·본문 크기 제한을 확인했다. 별도 임시 디렉터리의 새 경기 DB만 사용했고 원본 선수 DB는 열지 않았다.
- [시즌·커리어 회귀](../validation/DiamondSeason/VALIDATION.json): 371개 통과, 합성 기록으로 720경기 완주 및 다음 시즌·육성 경계 검사.
- [친선 HTTP 회귀](../validation/DiamondMatch/README.md): 1,441개 통과. 동시 입력·재시도·ETag·격리·만료·양쪽 외형 저장 포함.
- `node WEB/validation/diamond-season-http.mjs`: 실제 선수 DB에서 37개 HTTP 검사 통과.
- 서버를 재시작한 뒤 `node WEB/validation/diamond-season-http.mjs --resume`: 7개 복원 검사 통과.
- `node WEB/validation/diamond-season-balance.mjs --full-season`: 실제 선수 DB의 전체 시즌 720경기/팀당 144경기, 17.849초. 팀 경기당 4.725득점, 타율 .25774, 홈런 .80972, 볼넷 4.90139, 삼진 7.25972. 선발 타자 원기록 평균 타율은 .27710. 다른 시드와 2025/2026년 270경기의 비교는 [밸런스 문서](../validation/DiamondSeason/BALANCE.md)에 있다.
- 최신 번들의 실제 브라우저 로그에서 셰이더/렌더 오류 없음. 동작·형상 검사는 장치별 프레임 속도를 보장하지 않는다.

HTTP 검사는 사용자 플레이 저장소와 분리한 상태 디렉터리에서 실행했다. 검증용 소유자 쿠키·실제 상태 DB는 소스나 ZIP에 포함하지 않는다.

## ZIP 이관 검증

저장 코드 추가 전의 전체 경기 소스 ZIP을 기존 작업 저장소와 다른 경로에 풀고, 압축 해제한 `WEB` 디렉터리에서 .NET SDK `8.0.423`으로 다음 명령을 실행해 성공했다. 기존 작업 폴더의 빌드 결과에 의존하지 않고 이관된 소스로 게시용 실행 파일을 생성하는 과정까지 확인했다.

```powershell
dotnet publish server/src/NaverSabermetrics.Web/NaverSabermetrics.Web.csproj -c Release -o published
```

압축 해제한 `WEB/diamond-game`에서도 `npm ci`와 `node build.mjs`를 실행해 성공했고, 원본 작업 폴더와 같은 `game-G5JBEHOD.js` 및 `game-M3D4QSEG.css`가 생성됐다.

이 검증은 로컬 `published` 폴더 생성이며 온라인 서버 배포는 아니다.

## 저장 코드 추가 검증

- [저장 코드 독립 HTTP 검증](../validation/DiamondSaveCode/README.md): 90개 통과, 컴파일 경고 0. 서로 다른 쿠키의 최신 상태 복원, 서버 재시작, 기존 다른 저장 보존, 실패 시 쿠키/프로필 불변, 동시 요청과 보상 중복 방지, 요청 제한을 확인했다. 원본 선수 DB는 열지 않았다.
- 변경 후 시즌 회귀 371개와 친선 HTTP 회귀 1,441개를 다시 실행해 통과했다.
- TypeScript 및 시즌 UI 회귀 통과. 게임 저장과 코드 요청의 순서, 복원 응답 유실 후 동일 코드 재시도, 실패 시 기존 화면 유지, 성공 시 이전 상태를 비우는 전체 새로 고침을 검사했다.
- 저장 코드 추가 당시 화면 번들 `game-SW3DTGOQ.js`·`game-HJ5DVFFI.css` 및 .NET 웹 앱 빌드 통과(경고 0, 오류 0). 클립보드 성공·거절·미지원·응답 없는 경우의 1.5초 대체 안내와 타이머 정리도 UI 회귀에 포함했다. 실제 브라우저에서 코드 복사 성공을 확인했다.

## 경기장 안 조작 검증

2026-09-13에 전체 경기와 타석 연습의 구종 선택·투구 버튼을 경기장 안으로 옮기고, 스윙 안내를 화면 직접 클릭·터치 기준으로 통일했다. 버튼 영역만큼 3D 화면 높이를 조정해 스트라이크존을 가리지 않는다.

- 실제 브라우저의 전체 경기에서 다음 투구 후 야구장 화면을 클릭해 스윙이 전송되고 헛스윙·타이밍 -185ms로 판정되는 것을 확인했다. 구종 목록에서 슬라이더를 선택했을 때 선택 상태가 바뀌었다.
- 데스크톱 전체화면과 390×844 모바일에서 버튼이 경기장 안에 표시되고 캔버스 하단과 조작 영역 상단이 맞닿는 것을 확인했다. 모바일 문서 폭은 375px, 경기장 폭은 351px였고 구종 버튼 높이는 전체 경기 44px 이상, 타석 연습 48px였다.
- 모바일 타석 연습에서 화면 안의 커브를 선택하고 투구 버튼을 클릭해 실제 122.7km/h 커브·파울 판정까지 확인했다. 사용자 플레이와 분리한 검증용 저장소만 진행했다.
- `tests/scene-input.mjs`는 실제 화면 입력 연결을 사용해 마우스·펜·짧은 터치의 단일 스윙, 조준 고정, 스크롤·취소·다중 터치·긴 터치의 입력 방지, UI 버튼 이벤트 분리, 선택 직후 같은 이벤트 턴의 구종 반영, 충전·진행 중 선택 잠금, 다른 포인터의 릴리스 무시, 포커스 이탈 시 충전 취소를 검사한다.
- 최종 TypeScript, `scene-input.mjs`, `swing-input.mjs`, `season-ui.mjs` 검사 통과. 화면 번들은 `game-WN22VJVZ.js`·`game-ZVWB26SE.css`이며 .NET 웹 앱 빌드도 경고 0·오류 0으로 통과했다. 로컬 플레이 서버에 같은 번들을 반영했다.

## 자동 다음 투구와 동작 개선 검증

2026-09-13에 AI 상대 타격의 첫 공·다음 공을 기본 자동으로 바꾸고 화면 안의 일시정지·재개 버튼을 추가했다. 전체 경기·친선·타석 연습이 공통 요청 제어와 결과 대기 시간을 사용한다. 투구는 1.8초 와인드업과 1.05초 회복으로 확장하고, 스윙은 입력 전 로딩과 골반·몸통 분리 회전·앞발 버팀·뒤꿈치 피벗·팔로스루를 추가했다. 스윙 접촉 시각 95ms와 릴리스 좌표는 유지한다.

- 최신 TypeScript 엔진으로 108투구·756판정 기준 자료를 다시 생성하고 C# API 회귀 총 42,373개를 통과했다. AI 2.2초/PvP 2.6초 준비 시간을 포함한 양쪽 엔진 정합, 저장·AI/PvP·입력/재시도 검사를 확인했다.
- 준비 시간 변경 후 시즌 회귀 371개(720경기 완주), 친선 HTTP 회귀 1,441개(수동 216투구·연장 12회)를 다시 통과했다. 친선의 릴리스 예약 기대값도 의도한 2,600ms로 갱신했다. 합성 DB만 사용했다.
- 검증용 리그 실제 화면에서 별도 투구 버튼 없이 김진욱의 투구 수 14→16 증가를 관찰했다. 일시정지 후 16구 유지, 재개 직후 저장 창을 열었을 때 16구 유지, 닫은 뒤 재개 가능을 확인했다. 검증용 상태 디렉터리만 진행했다.
- 타석 연습에서도 타석 시작 후 첫 공과 다음 공이 자동으로 진행됐고 141.0km/h·143.0km/h 커터를 관찰했다. 화면 안 일시정지 버튼의 동작을 확인했다. 모바일 390×844에서 문서 폭 375px·경기장 351px·버튼 90×44px로 가로 넘침이 없었다.
- 별도 로컬 검토 화면에서 실제 3D 선수 모델의 투구·스윙 연속 프레임을 확인했다. 준비·릴리스·팔로스루를 나누어 검사하며, 실제 경기의 타구 카메라도 접촉 후 320ms 기다린 뒤 850ms 동안 이동하고 타자는 스윙을 마친 뒤 주자 모델로 전환한다.

- 실제 눈 삼각형을 잘라 피부 커버와 움직이는 윗 속눈썹을 만들었다. 눈 표면과 피부 커버의 간격은 0.150mm, 속눈썹은 0.220mm다. 열린 속눈썹의 중심선·폭을 유지하고 깊이는 실제 눈에 맞춰 최대 0.352mm 조정했다. 기존 홍채·동공 텍스처와 얼굴·관절은 보존한다.
