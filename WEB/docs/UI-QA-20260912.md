# 웹 화면 QA — 2026-09-12

로컬 실제 DB 미리보기에서 홈, 기록실, 선수·팀 상세, 경기 달력·상세, 야구게임을 직접 열어 확인했다.

## 수정

- 옅은 회색 보조 글자와 주황색 활성 항목의 대비를 높이고, 본문·기록표·설명 글자를 키웠다.
- 휴대폰 상단 메뉴를 두 줄로 배치했다. 주요 입력창은 16px 글자와 44px 높이를 사용한다.
- 모바일 기록표는 선수명만 가로로 고정한다. 적용 조건 열도 옆으로 이동하여 성적이 보이는 공간을 확보하고, 표 제목의 세로 고정은 유지한다.
- 기록표의 가로 스크롤 안내와 키보드 포커스를 추가하고, 고정 footer가 내용을 가리지 않도록 바꿨다.
- 모바일 경기 달력은 날짜·요일이 있는 목록으로 표시한다. 홈 순위 카드의 불필요한 높이도 줄였다.
- 선수 상세 탭을 줄바꿈하고 프로필 글자 겹침을 방지했다. 모바일 백분위는 서버의 같은 수치를 HTML 막대 목록으로 표시하여 SVG 축소로 숫자가 작아지는 문제를 해결했다.
- 게임 선수 선택 카드를 모바일에서 한 열로 넓혔다. 구종·조작 안내·선수 이름의 크기와 대비를 높였다.
- 필터 초기화 버튼의 `id="reset"`이 form의 `reset()` 메서드를 가려 발생하던 오류를 수정했다. 초기화는 연도를 유지하고 선수명과 상세 조건을 지운다.

## 확인 결과

- Chrome에서 320, 390, 768, 1440px 화면의 메뉴 이동, 필터 검색·초기화, HR 정렬, 표 가로 스크롤, 선수 검색, 선수 연도별 기록, 팀 선수 목록, 경기 상세 펼치기, 게임 모드·선수 선택을 확인했다.
- 검사한 주요 페이지에 문서 전체의 가로 넘침과 JavaScript 오류가 없었다.
- 백분위 표시는 320, 390, 1440, 1920px에서 확인했다. 작은 화면에는 HTML 목록, 큰 화면에는 SVG가 표시된다.
- Chrome 터치 이벤트로 타자·투수 모드의 경기 시작 전/후 세로 스와이프를 확인했다. 스와이프가 게임 동작을 발생시키지 않고, 이후 스윙·투구 요청은 성공했다.
- 게임 번들 빌드, JavaScript 구문 검사, .NET Release publish, `git diff --check`가 통과했다. 배포용 wwwroot에도 같은 정적 파일을 반영했다.

실제 iPhone Safari 기기 검증은 하지 않았다. 모바일 검증은 Chrome의 터치·화면 크기 에뮬레이션이다. 통계 계산과 DB는 변경하지 않았다.
