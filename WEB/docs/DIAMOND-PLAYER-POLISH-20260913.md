# DIAMOND 선수 모델 개선 (2026-09-13)

최신 게임 소스를 통합한 `5610b98` 위에 선수 모델과 미리보기 개선을 추가했다. 웹 기록실의 DB 로스터와 게임 규칙을 사용하는 기존 구조를 유지한다.

## 화면에서 달라진 점

- 얼굴: 눈 중심 간격을 88mm에서 72mm로 줄이고 눈꺼풀·눈썹·음영을 함께 옮겼다. 모자 아래에서도 눈이 읽히도록 눈꺼풀 안쪽의 눈 표면을 조정하고, 눈두덩·볼·턱·머리카락의 기존 정점에 약한 색 변화를 넣었다.
- 유니폼: 셔츠와 바지의 큰 주름을 기존 정점으로 표현하고, 어깨 뒤와 옆구리의 봉제선을 실제 셔츠 표면에 맞췄다. 팀 색 위에 약한 직조 무늬를 입혔다.
- 장갑과 배트: 직물·가죽·목재에 서로 다른 색 결을 적용했다. 선택한 글러브 색이 테두리와 포켓까지 이어지고, 어두운 가죽의 포켓은 몸체보다 어둡게 유지된다.
- 신발: 앞코의 갑피가 밑창에 닿도록 높이를 조정했다. 끈의 매듭과 봉제선도 실제 갑피 표면에 맞췄다.
- 스윙: 공을 친 뒤 회복 구간에서 손이 어깨 쪽으로 급히 접히던 동작을 완화했다.
- 선수 미리보기: 좌우 타석에 맞춰 타자의 얼굴이 보이는 초기 각도, 키에 비례하는 카메라 거리, 전신/얼굴·장비 확대 전환을 제공한다. 양타자의 반대 타석 보기에도 카메라 방향을 함께 반전하고, 투구 손·폼 변경 시 타석과 카메라를 함께 초기화한다. 확대·회전·투구폼 버튼의 높이는 최소 44px이다.

## 구조와 동작

모델 삼각형과 메시 수를 늘리지 않았다. 기존 어깨·팔꿈치·손목·고관절·무릎·발목의 관절 위치와 몸집 변경, 좌우 반전, 투구폼을 사용한다.

| 기본 모델 | 메시 | 삼각형 |
|---|---:|---:|
| 타자 | 54 | 42,528 |
| 투수·야수 | 53 | 46,914 |
| 포수 | 69 | 49,664 |

표는 모델 본체 기준이다. 실제 경기의 투수 손 그립·공과 타자의 별도 배트는 역할에 따라 추가된다. 포수까지 기존 50,000 삼각형 예산 안에 있다.

스윙 변경은 560~780ms의 회복 구간에만 적용한다. 95ms 접촉 시점, 접촉 이전과 직후 궤적, 공의 비행과 판정에는 영향을 주지 않는다.

신발 봉제선의 표면 맞춤은 좌우 두 형태의 이동량만 1,776바이트 숫자 캐시로 재사용한다. 모델끼리 geometry나 material을 공유하지 않는다. 캐시 전후 6쌍의 신발에서 144개 속성 배열과 12,738개 정점 및 인덱스가 바이트 단위로 같았으며, 한 신발의 수정·해제가 다른 신발과 이후 생성에 영향을 주지 않는 것도 검사했다.

## 검증 기록

- 옷 형상: 3개 체형의 기존 정점·삼각형·관절·스킨 가중치 및 경계 검사 322,029개 통과.
- 얼굴: 좌우·신장·체형을 포함한 54개 모델과 눈꺼풀·깜빡임, 포수 마스크의 18개 시선을 검사했다. 코 형상은 기존과 같다.
- 스윙: 보호해야 하는 기존 포즈 비교 98,928개 일치. 좌우 타격·155/185/215cm·3개 체형의 회복 구간에서 손목과 배팅 장갑 연결을 확인했다.
- 신발: 앞발 18개 지점에서 갑피/밑창 틈이 없고, 봉제선 중심 37개 지점은 가죽에서 최대 약 0.45mm 이내다. 스터드의 기존 접지 높이는 유지한다.
- 재질: 색공간, 타일 경계, 독립적인 텍스처 소유와 해제, 템플릿 캐시 상한을 검사했다. 256×256 색 결 3종을 추가하여 최대 템플릿 캐시는 2.75MiB다.
- 전체 회귀: 최종 소스에서 프런트엔드 43개 테스트 그룹, TypeScript 검사, 프로덕션 번들 빌드와 서버 Release 게시 빌드를 통과했다.
- 미리보기: 320/390/1000px에서 타자·투수, 155/215cm, 전신·확대 및 좌타·양타 전환을 담은 화면 33개를 확인했다. 좌우 투구 손과 3종 투구 동작의 미리보기 6개 및 44px 조작 영역도 확인했다.
- 전신 구도: 기본 카메라의 496개 대표 동작을 실제 스킨 정점으로 투영했다. 6투구폼·좌우 타격·155/215cm·두 체형, 좁은 태블릿 전환을 포함한 14개 화면 조건에서 잘림이 없었고 최소 여유는 약 20.8px였다. 사용자가 회전한 임의 각도와 의도적인 확대 화면은 이 검사 범위에 포함하지 않는다.
- 기록실 통합 화면: 320/390/1440px에서 기존 선수 저장을 불러와 전신·확대·회전·스윙 재생을 확인했다. 바깥 페이지와 게임 iframe의 가로 넘침, JavaScript 오류, 실패한 로컬 요청이 없었다.
- 선수 설정: 통합 화면의 같은 3개 폭에서 좌투 언더핸드·215cm·건장한 체형과 검은 글러브를 미리 보고, 390px에서는 선수 생성 후 새로고침하여 설정 보존까지 확인했다. 6개 투구폼 선택과 원래 폼 복귀를 확인하고, 양타 타석을 바꾼 뒤 투구 손·동작을 변경하는 4개 경우에도 카메라 초기화가 일치했다.
- 모바일 조작: Chrome 터치 에뮬레이션에서 한 번의 터치가 스윙 한 번을 전송하고, 세로 스와이프는 스윙 없이 부모 페이지를 스크롤했다. 기록실의 다른 탭에서는 자동 투구·공수 진행과 폴링이 멈추고, 게임 탭 복귀 시 재개했다. 명시적인 일시정지도 확인했다. 실제 iPhone Safari 기기 검증은 포함하지 않는다.
- 저장 호환: 최종 모델 빌드로 서버를 재시작한 뒤 기존 선수·훈련·경험치·리그 저장을 불러오는 실제 HTTP 검사 7개를 통과했다. 원본 선수 DB와 게임 저장 DB는 기존처럼 분리한다.

## 렌더링 비용 확인

실제 경기의 타격/투구 카메라, 구장, 모바일 거리별 디테일 조정과 역할별 대기 자세를 사용하는 별도 장면에서 비교했다. 캔버스는 366×350px, pixel ratio 1.4다. 14개 선수 모델을 생성하고 타격 시점에서는 11개, 투구 시점에서는 12개를 표시했다.

Chrome SwiftShader에서 5초 준비 후 각 60초 동안 관측한 결과다. 소프트웨어 렌더러의 상대 비용 확인이며, 실제 iPhone이나 통신·HUD를 포함한 전체 앱의 FPS 측정은 아니다.

| 항목 | 기존 | 개선 후보 |
|---|---:|---:|
| 타격 시점 평균 FPS | 1.27 | 1.25 |
| 투구 시점 평균 FPS | 1.90 | 1.85 |
| 타격 시점 draw calls | 562 | 562 |
| 투구 시점 draw calls | 509 | 509 |

이 한 쌍의 관측에서 FPS 변화는 타격 −1.7%, 투구 −2.6%였다. 60초 동안 geometry/texture 개수는 증가하지 않았으며, 장면 정리 후 네 경우 모두 geometry 0개와 렌더러 내부 texture 1개가 남았다. 그 직후 렌더러도 해제했다. 실제 기기의 프레임 유지나 통계적 유의성을 보장하는 수치는 아니다.

시간 측정 후 확정한 눈 간격 72mm/기존 코 조합도 별도 장면에서 확인했다. 할당 geometry/material/texture 및 draw call 수는 같았다. 화면에 실제 그린 삼각형은 타격 +28개, 투구 +16개였으며, 타격 한 프레임 추적에서 눈꺼풀 리본의 동적 drawRange 변화가 원인임을 확인했다. 할당 정점·인덱스 용량은 늘어나지 않았다. 이 마지막 확인에서는 FPS를 다시 측정하지 않았다.

## 모델 초기 구성 비용

로컬 Chrome에서 실제 경기의 14개 선수와 장비를 생성하는 CPU 작업을 기존/최종 버전 각각 새 페이지 3개로 비교했다. 페이지마다 첫 생성 1회와 후속 생성 2회, 총 18회를 교차 순서로 측정했다. 첫 생성 중앙값은 902.1→974.1ms, 후속 생성은 644.3→744.0ms였다. 기존보다 약 72~100ms가 늘었다.

이 측정에는 구장 생성, DB·네트워크, 스크립트 다운로드, 셰이더 컴파일·GPU 업로드가 포함되지 않는다. 실제 iPhone이나 전체 게임 시작 시간을 뜻하지 않으며, 신발 캐시만의 속도 효과를 분리한 실험도 아니다. 모든 반복에서 소유 리소스 개수는 안정적이었고 정상 해제를 확인했다. 14명 전체의 geometry 배열은 22.54→23.56MiB, 소유 Canvas 이미지의 원시 픽셀 크기는 65.25→73.75MiB로 늘었다. 이 값은 브라우저 전체 메모리 사용량이 아니다.

## 남은 표현 한계

공통 절차형 모델을 사용하는 게임으로, 선수별 얼굴 스캔이나 사진 기반 외형은 제공하지 않는다. 확대 QA에서는 기존 포수 어깨 보호대/끈과 옷의 일부 교차, 포수 하체의 거친 그림자, 좌투 언더핸드 후속 동작에서 미트와 등의 일부 교차도 확인했다. 이번 변경 전후에 같은 현상이 있으며 이 릴리스에서 해결했다고 간주하지 않는다.
