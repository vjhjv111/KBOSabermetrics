# 분석실 사용·개발 안내

분석 수식 문서 기준: **Analysis Lab v1 · 2026-09-12**. 기존 WAR 계산 버전과 별도로 관리하는 분석 기능의 기준이며, API 응답에 별도 버전 필드를 추가한 것은 아니다.

현재 검증 사본은 **2026년 정규시즌 622경기·191,466투구**, 경기일 2026-03-28~2026-09-11이다. 사용자의 전체 DB나 시즌 종료 자료를 뜻하지 않는다. 검증에 사용한 파일은 작업 폴더의 `season-validation/season-20260911-225618-4140b8/season.db`다.

## 사용 방법과 8개 탭

상단 **분석실**에서 시즌·팀·선수를 고르고 **분석 조회**를 누른다. 선수 명단은 해당 시즌의 실제 투구에 등장한 선수로 구성한다. 공략 지도·볼배합·최근 변화·투구수·재대면은 선수 선택이 필요하다. 불펜 사용량은 선수를 비우면 팀 또는 리그 투수들을 함께 볼 수 있다.

| 화면 | 조회하는 내용 | 해석할 때 확인할 점 |
|---|---|---|
| 공략 지도 | 구종·좌우·투구 전 카운트별 5×5 코스 표, 스윙·헛스윙·루킹 스트라이크·SLG | 중앙 3×3이 존 안이다. 좌표 누락·범위 밖 투구의 제외 수를 확인한다. |

모든 조회는 선택 연도 정규시즌 `kbo_r`에 한정하며 올스타전·시범경기·포스트시즌은 제외한다. `—`는 분모 없음 또는 자료 누락이고, 0은 관측된 0이다. 작은 표본의 비율은 변동이 크므로 표본 수와 함께 본다. 화면의 설명에 각 탭에서 적용하거나 적용하지 않는 조건을 표시한다.

## 계산 기준과 제한

- **공통 비율:** 스윙%=스윙/투구×100, 헛스윙%=헛스윙/스윙×100, K%=삼진/공식 완료 PA×100, BB%=(볼넷 또는 고의4구)/공식 완료 PA×100, SLG=TB/AB. 비율의 API 값은 0~100, SLG는 비율 원값이다.
- **종료 타석:** 구종·좌우·카운트별 PA 성적은 실제 마지막 투구와 공식 완료 PA를 먼저 연결한 뒤 조건을 적용한다. 조건에 맞는 마지막 투구를 실제 종료 투구로 간주하지 않는다. 투구 조건이 없으면 최근 변화·재대면의 PA에는 무투구 PA도 포함한다.
- **존:** 원본 X(ft)의 좌우 ±0.7083ft와 `정규화 높이=(홈 통과 Z−존 하단)/(존 상단−존 하단)`를 사용한다. 안쪽을 가로·세로 각각 3등분하고 양 바깥 구역을 더해 5×5로 만든다. X ±10ft, Z −5~15ft, 하단 0~6ft, 하단보다 높고 8ft 이하인 상단을 만족하지 않으면 제외한다.
- **볼배합·구속:** 같은 PA에서 실제 연속 투구만 연결한다. 구속 차이는 현재−직전 km/h이고 양쪽 모두 40~180km/h인 쌍만 평균한다. 최근 변화의 구속도 같은 범위에서 구종별 유효 관측 수로 가중한다.
- **최근 N경기:** 날짜·경기 ID 순으로 정렬한 현재 경기와 직전 N−1경기다. 초반에는 존재하는 경기만 사용한다. 해당 구종이 없었던 경기도 경기 창에 포함하며, 일별 평균을 다시 단순 평균하지 않는다. 경기와 구종별 구속 표는 각각 최근 최대 500행이다.
- **투구 순번·재대면:** PA마다 초기화되는 `ActualPitchIndex` 대신 `NormalizedEvents.ChronologicalIndex`로 경기 내 해당 투수의 투구를 센다. 순서 자료가 없는 투구는 순번 분석에서 제외한다. 구간 PA는 실제 마지막 투구 구간에 한 번 배정한다. 무투구 PA는 구간에 배정하지 않는다. 같은 경기·투수·타자의 새 타석은 새 만남이며, 중단 PA도 만남 순번에는 포함하지만 공식 완료 PA 분모에는 제외한다.
- **최근 부하:** 기준일은 종료일 또는 DB의 해당 시즌 마지막 경기일이다. 3일은 기준일−2일~기준일, 7일은 기준일−6일~기준일이며 더블헤더는 별도 등판이다. 휴식일은 `max(0, 기준일−마지막 등판일−1)`이다. 시작일·구종·좌우·카운트는 적용하지 않는다. 박스스코어 `PitchCount`가 누락된 창은 합계를 비워 둔다. `AppearanceSequence=1`은 선발, 2 이상은 구원, 나머지는 미상이다. 표 이름과 관계없이 선발 투구도 부하에 포함하며 피로·부상 위험을 추정하지 않는다. 박스스코어 테이블이 없으면 수집 투구 수로 대체하고 역할은 미상으로 표시한다.
- **RE24:** 0아웃·무주자에서 시작해 3아웃으로 종료하고 점수·아웃 상태가 이어지는 공수 이닝만 사용한다. 끝내기·미완료·불연속 이닝은 제외한다. `RE=관측 상태부터 같은 공수 이닝 종료까지 득점의 평균`, 그룹 변화는 `그룹 득점+다음 상태 RE−시작 상태 RE`다. 타석 밖 주자 득점도 반영한다. 행동표는 번트/도루/진루가 포함된 중계 그룹 전체의 관측값으로, 한 그룹 안의 타격·복수 주자 행동을 분리할 수 없다. 기준 RE는 선택 기간·팀 경기의 전체 선수 표본이며 선수 조건은 행동표에만 적용한다.
- **궤적:** 각 축에 `위치(t)=초기 위치+초기 속도×t+0.5×가속도×t²`를 적용한다. 단위는 ft·초이며 보통 y0=50ft 기준점부터 저장된 홈 도달 시간까지다. 홈 기준면·종점 불일치, 계수 누락, 비정상 시간은 재생하지 않는다. 최대 40구/타석·25점/투구이고, 궤적이 없어도 실제 투구 행은 남긴다.
- **출처:** 전체 네이버 원본 JSON과 최초 박스스코어는 이 관계형 DB에 보존되지 않는다. 보존된 결과 이벤트 문구만 원문으로 표시한다. 공식 중계는 이닝·공수·타순·선수·공식 PA 순서가 맞아야 연결한다. 원문 JSON·내부 경로를 응답하지 않으며 정정 공지·저장 상태·비교 가능한 공식 필드를 구분한다.

## API와 코드

`POST /api/analysis`를 기존 서버의 인증·요청 제한·조회 게이트 안에서 실행한다. `catalog`는 선택 목록용이고 나머지 section 값은 `zones`, `sequences`, `trend`, `times`, `workload`, `expectancy`, `replay`, `provenance`다.

요청 필드는 `section`, `year`, `code`, `role`, `team`, `start`, `end`, `pitchType`, `stance`, `count`, `gameId`, `paId`, `page`, `window`다. 날짜는 `YYYY-MM-DD`, 좌우는 `L`/`R`, 카운트는 `0-0`~`3-2`, window는 1~30이다. 응답은 `section/title/notes/summary/tables/chart/hasMore/page`이며 표마다 열의 이름·표시 형식을 제공한다.

새 분석은 `DatabaseCacheService.DatabasePath`에 **SQLite ReadOnly 연결**을 열고 매개변수 SQL, `QuerySeconds`, 요청 취소를 사용한다. 데이터 마이그레이션·스키마 변경·원본 갱신은 수행하지 않는다. 일반 표는 최대 500행, 선수 카탈로그는 역할별 500명 단위, 타석/경기 선택 목록은 50행 단위다. 불펜 상위 표는 100명이다.

저장소 루트에서 실행한다. `$analysisDb`는 검사할 실제 사본의 절대 경로로 바꾼다. 출력 경로를 분리하면 이미 실행 중인 웹 서버의 DLL과 충돌하지 않는다.

화면 회귀 검사는 `WEB/validation/analysis-page-smoke.mjs`를 실행한다. `QA_URL`로 테스트 서버 주소를 지정하고 Playwright와 Chromium을 준비한다. `CHROMIUM_EXECUTABLE`로 설치된 Chrome 경로, `QA_OUTPUT`으로 스크린샷·결과 보고서 폴더를 지정할 수 있다. 테스트는 2026년 실제 검증 사본의 김도영·곽빈을 사용한다.

## 팀명 색상

홈·기록실·선수/팀 페이지·경기 상세·분석실의 팀명은 기존 유니폼 팔레트를 기반으로 구단별 색상을 쓴다. 흰 배경에 맞춰 밝기를 조정했으며 10개 팀의 글자 대비는 최소 5.39:1이다. SSG/SK·해태·넥센·빙그레 등은 같은 구단 색상에 연결하고 표시된 역사적 명칭은 보존한다. 복수 팀은 각각 색칠하고 미상 팀은 중립색으로 남긴다. 네이티브 선수 선택 항목처럼 부분 글자색을 지정할 수 없는 컨트롤은 기본 글자색을 유지한다.

`WEB/validation/team-color-smoke.mjs`로 390px 터치·1440px 데스크톱의 10개 팀 색상, 명칭 연결, 복수 팀, 팀 필터 초기화, 각 페이지 표시와 본문 넘침을 검증했다. 이 검사는 `BASE_URL`, `CHROME_PATH`, `QA_OUTPUT` 환경변수를 받는다.
