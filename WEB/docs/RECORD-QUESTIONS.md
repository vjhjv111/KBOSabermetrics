# 기록 질문 시험 기능

웹 질문 UI와 기존 POST /api/ask는 비활성화했다. 카톡봇 /팬자이 명령은 POST /api/bot/ask를 사용한다. X-Fanzai-Bot-Key 헤더를 서버 FANZAI_BOT_API_KEY(32자 이상)와 비교하며, 이 인증된 경로만 CSRF 쿠키를 요구하지 않는다. 기존 IP 제한은 적용한다. 모델은 조회 계획만 만들고 수치와 표는 읽기 전용 DB에서 계산한다. 질문·스키마·보유 연도만 OpenAI로 전달하며 DB 결과는 보내지 않는다. 임의 SQL을 실행하지 않는다.

## 지원 범위

- 기존 ViewRegistry에 등록된 타자/투수 기록 지표: 기본, 심화, 가치, 구종 등. 질문과 관련된 지표 이름을 후보로 전달하고 실제 속성명·공개 정책을 검증한다. 운영에서 숨긴 지표는 그대로 숨긴다.
- 시즌·팀·통산, 정규/시범/포스트시즌, 날짜·팀·선수·상대팀·홈원정·구장, 단일 회차/연장, 주자·아웃·볼카운트·점수상황, 기존 기록실에서 지원하는 최근 경기/일수 필터.
- 기존 기록실의 필터 조합 제약을 그대로 적용한다. 임의 개수의 최근 경기나 초말 분리, 여러 지표 비교는 아직 지원하지 않는다. 어떤 자연어 표현도 완벽하게 해석한다고 보장하지 않는다.
- 개별 타석 WPA: 정규시즌 연도/기간/팀/선수/회차, 부호 있는 WPA 또는 절댓값 순위. 경기 ID·타석 번호·날짜·타자·투수·결과·원본 WPA 반환. 투수 관점은 타자 시점의 부호 반전이다. 누락 WPA는 0으로 채우지 않는다. 개별 투구나 독립 주루 플레이 순위는 별도 지원이 필요하다.
- 회차별 투수 IP/ERA/실점은 기존 기록실의 타석 기반 근사치(*)다. 공식 자책점·승계주자 책임과 차이가 날 수 있다.
- 최소 0.1/0.2이닝은 야구 표기 1/2아웃이다. 회차·명시한 최소 표본·일부 주요 필터를 질문 원문과 교차 검증하고 누락 시 중단한다.

## 설정과 한도

기본 비활성화. 운영 환경:

| 변수 | 값 |
|---|---|
| OPENAI_API_KEY | 비밀 키, 저장소/채팅에 붙여넣지 않음 |
| RecordQuestions__Enabled | true |
| RecordQuestions__Model | gpt-4.1-mini |
| RecordQuestions__DailyLimit | 1000 |
| RecordQuestions__PerIpDailyLimit | 10 |
| RecordQuestions__MaxInputTokens | 3000 |

로컬 Start-RecordQuestions.ps1만 명령행 인자로 전체 10,000/IP 1,000회를 지정한다. 커밋/푸시 시 운영 기본값은 전체 1,000/IP 10을 유지한다. Render의 기존 환경변수는 기본값을 덮어쓰므로 배포 때 동일 값인지 확인한다.

질문 최대 600자. instructions와 도구 스키마를 포함한 전체 입력을 /v1/responses/input_tokens로 확인하고 3,000 초과 또는 계수 실패 시 응답 생성을 중단한다. 계수 요청에도 질문은 전송된다. 출력 최대 900토큰, 동시 AI 질문 1건. 계수 1회와 응답 생성 1회이며 결과 문장은 서버가 작성한다.

일일 사용량은 한국시간 기준 StateDirectory/record-question-usage.json에 저장한다. 실패/계수 초과도 시도 횟수에 포함한다. 단일 서버 프로세스용 한도이며 다중 인스턴스에서는 중앙 저장소가 필요하다. 요청 수 한도는 달러 한도와 다르다.

## 로컬 실행

PowerShell에서 WEB/scripts 디렉터리로 이동 후:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-RecordQuestions.ps1
```

숨김 프롬프트에 키를 입력한다. 키는 프로세스 환경에만 보관한다. 로컬 API는 http://127.0.0.1:5128/api/bot/ask 이다. 웹에는 질문 버튼이 없다. 테스트 공유 키 파일은 %TEMP%/Fanzai-RecordQuestions/fanzai-bot-key.txt에 생성된다. 봇 설정은 WEB/integrations/kakao/README.txt를 따른다. 소스 수정 후에는 기존 실행창에서 Ctrl+C로 종료하고 같은 명령으로 다시 빌드/실행한다.

API 키에는 Responses 생성과 입력 토큰 계수 권한이 필요하다. 실제 모델 호출은 비용이 발생한다.

## 검증

WEB/validation/RecordQuestions 프로젝트는 가짜 모델/HTTP 응답으로 토큰 상한·조건 검증·운영 한도를 확인한다. SABER_QA_DB 지정 시 실제 DB의 기본/9회/WPA 타석 조회를 확인한다. 외부 OpenAI 호출은 하지 않으므로 실제 자연어 해석 품질·키 권한을 검증한 것은 아니다.
`n구단명은 QuestionTeams의 고정 매핑으로 정규화한다. 한화/한화이글스=HH, KIA/기아=HT 등 정식명·약칭·띄어쓰기를 지원한다. 명확한 단일 구단은 AI의 잘못된 코드를 교정하고, 상대 구단/다중 구단이 모호하거나 누락되면 중단한다. 적용 조건에는 내부 코드 대신 구단명을 표시한다.

인증된 /api/bot/ask 호출만 IP별 일일 한도에서 제외한다. 전체 일일 한도, 순간 IP 요청 제한, 동시 요청 제한은 유지한다. 예외 여부는 요청 JSON이 아닌 인증된 서버 엔드포인트에서 지정한다. 일반 조회의 IP 10회 기본값은 유지한다.
