# KBO 진출확률 모델과 과거 시즌 검증

2026 시즌의 기본 진출확률은 피타고리안 승률에 상대 강도 보정과 경기수에 따른 평균 회귀를 적용한다. 선택된 계수는 **상대 보정 α=0.5, 회귀 기준 k=40경기, 홈 로그오즈 H=0**이다. 홈 효과를 계산하는 기능과 공식 홈·원정 배정은 구현되어 있으나, 사전 검증에서 선택된 기본값에는 고정 홈 가산점을 넣지 않는다.

모델 버전은 `pyth-sos-logit-v1-20260913`이다. 2020–2023년으로 후보별 계수를 맞추고 2024년으로 모델을 선택한 뒤, 2025년 결과를 평가하기 전에 선택을 고정했다. 독립 테스트 한 시즌에서 기존 모델보다 개선되었으며, 장래 정확도를 보장하는 결과로 해석하지 않는다. 화면에 표시하는 피타고리안 승률과 예상승 자체는 기존 식을 유지한다.

## 홈 화면에서 계산 과정 확인

홈 팀 순위표 아래의 **계산식 보기**를 누르면 접혀 있던 설명이 펼쳐진다. 설명은 ① 득실점으로 기본 전력 계산 → ② 상대 수준과 경기 수로 보정 → ③ 남은 경기별 승리 확률 계산 → ④ 시즌을 10,000회 반복해 상위 5팀 집계의 네 단계로 구성한다. 적용 계수와 기호의 뜻, 과거 검증 결과와 한계도 함께 표시한다. 홈 계수 H=0은 검증에서 선택한 기본값이며, 홈 이점이 없다는 결론으로 표시하지 않는다.

**현재 기록을 공식에 넣어 보면**에서 홈 팀과 원정 팀을 선택할 수 있다. 두 팀의 경기수·득점·실점·피타고리안 승률·회귀 가중치·보정 전력을 보여 주고, 전력 차이를 경기 승리 확률 식에 대입한다. 같은 팀끼리는 선택할 수 없다. 화면의 수치는 반올림하지만 계산에는 서버가 반환한 원래 정밀도를 사용한다.

이 예제는 `POST /api/home`의 `forecastDetails`를 사용한다. `PlayoffModel.ComputeCalibrated`가 진출 시뮬레이션에 사용한 **동일한 팀 강도 배열**에서 상세값을 반환하므로, 브라우저가 별도로 전력을 추정하거나 보정 계수를 다시 맞추지 않는다. 각 팀에는 `team`, `g`, `rf`, `ra`, `pyth`, `rawLogOdds`, `regressionWeight`, `rating`을 제공한다. 제공 조건을 충족하지 않는 연도·기록에서는 상세 배열이 비어 있고 예제 대신 안내를 표시한다.

예를 들어 2026-09-12까지 적재된 로컬 검증 DB에서 두산을 홈, NC를 원정으로 선택하면 다음과 같다. 이후 DB가 갱신되면 화면의 입력과 결과도 달라진다.

| 입력 | 두산 · 홈 | NC · 원정 |
|---|---:|---:|
| 경기수 G | 127 | 121 |
| 득점 RF / 실점 RA | 590 / 540 | 623 / 633 |
| 피타고리안 승률 p | 54.0425% | 49.2715% |
| 회귀 가중치 λ | 0.760479 | 0.751553 |
| 보정 전력 r | 0.1169563713 | -0.0199579061 |

```text
r홈 − r원정 + H = 0.1169563713 − (−0.0199579061) + 0
                 ≈ 0.1369142774
P(두산 홈 승리 | 무승부 아님)
    = 1 / (1 + exp(−0.1369142774))
    ≈ 0.5341752000 → 53.42%
P(NC 원정 승리 | 무승부 아님) ≈ 46.58%
```

이는 선택한 대진의 **무승부를 제외한 1경기 승리 확률**이다. 그 대진이 실제 잔여 일정에 있다는 뜻은 아니며, 순위표의 **포스트시즌 진출확률**과도 다르다. 진출확률은 실제 남은 모든 대진을 반복해서 시즌 최종 순위를 집계한 값이다.

## 강도와 경기별 확률

팀 i의 완료 경기수는 `G_i = W_i + D_i + L_i`이며 무승부도 포함한다. `RF_i`, `RA_i`는 해당 시점까지의 득점과 실점이다. 지수 1.83은 기존 가정을 유지했으며 이번 검증에서 다시 추정하지 않았다.

```text
pyth_i = RF_i^1.83 / (RF_i^1.83 + RA_i^1.83)
p_i    = clamp(pyth_i, 0.000001, 0.999999)
s_i    = ln(p_i / (1 - p_i))
λ_i    = G_i / (G_i + k)
```

`M_ij`는 i팀이 홈에서 j팀을 상대로 치른 완료 경기수이다. 상대별 경기수와 홈 경기 편중은 다음과 같다.

```text
N_ij = M_ij + M_ji
v_i  = (Σ_j M_ij - Σ_j M_ji) / G_i
```

10개 팀의 잠정 강도 `z_i`를 아래 연립방정식으로 동시에 구한 뒤 평균을 0으로 맞춘다.

```text
z_i = λ_i × [s_i + α × Σ_j (N_ij / G_i) × z_j - H × v_i]
r_i = z_i - mean(z)

P(홈팀 h 승리 | 무승부 아님)
    = sigmoid(r_h - r_a + H)
    = 1 / (1 + exp(-(r_h - r_a + H)))
```

강한 상대를 많이 만난 기록은 상대 평균 강도를 더해 보정한다. 상대 보정 연립식은 로그오즈 공간의 선형 근사이며, 상대별 비선형 Log5 기대 승률의 가중평균을 정확히 역산한 식은 아니다. 홈 경기가 많아서 얻은 이점은 과거 기록에서 먼저 빼고, 다음 경기의 실제 홈팀에 H를 더한다. 홈·원정 횟수를 뒤집어도 H=0일 때 강도는 변하지 않으며, 같은 두 팀의 승률 합은 1이다.

k=40일 때 λ는 20경기에서 1/3, 40경기에서 1/2, 120경기에서 3/4이다. 이 값은 **로그오즈 강도의 경기수 가중 회귀**이며, 실제로 승률 .500인 경기 40개를 승패 기록에 추가하는 계산과 같지는 않다. α=0, k=0, H=0이면 기존 피타고리안·Log5 경기 확률과 일치한다. k=0이면서 α=1인 특이 연립방정식은 거부한다.

구현은 [PlayoffStrengthModel.cs](../server/src/NaverSabermetrics.Web/PlayoffStrengthModel.cs)에 있다. 입력의 비정상 수치, 음수 경기수, 팀별 전적과 대진수 불일치를 거부하며, 피타고리안 계산과 로지스틱 계산의 수치 범위를 보호한다.

## 남은 경기와 2026 공식 홈·원정 배정

시뮬레이션은 현재 승·무·패를 유지하고, **2026 공식 시즌 전체 홈·원정 배정에서 완료된 동일 대진을 뺀 경기**를 10,000회 진행한다. 팀 강도는 각 시뮬레이션 안에서 고정된다. 이후 승률 `최종 승수 / (144 - 현재 무승부수)`로 상위 5팀을 정한다. 진출선에서 승률이 같은 팀은 남은 진출 자리를 균등하게 나눈다. 팀별 확률의 합은 5이다.

KBO는 2025년 12월 19일 2026 일정을 발표했다. 우선 날짜가 정해진 675경기와 날짜 미정 45경기의 대진을 합쳐 720경기의 홈·원정 배정을 사용한다. 2026년에는 LG·삼성·NC·KIA·키움이 홈 73경기, 나머지 팀이 홈 71경기이다. [KBO 2026 일정 발표](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=11794)

2023년부터 상대별 배정은 홈·원정 각각 8경기에서 7·9경기로 바뀌었다. 따라서 남은 경기를 계산할 때 상대별 8·8 배정을 가정하면 안 된다. [KBO 2023 일정 발표](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=8590)

공식 첨부 일정에서 추출한 [2026 배정 증빙](playoff-calibration/home-quotas-2026.json)은 상대별 합계 16경기, 홈 방향별 7경기 또는 9경기, 총 720경기를 검증한다. 이 배정은 2026년에만 적용한다. 날짜 미정 경기도 상대와 홈팀은 포함하며, 우천 취소에 따른 실제 경기 날짜·순서·휴식일은 모델에 넣지 않는다. 완료 경기수가 공식 배정을 초과하거나 입력 전적과 맞지 않으면 확률을 계산하지 않는다.

일정 구현은 [PlayoffSchedule2026.cs](../server/src/NaverSabermetrics.Web/PlayoffSchedule2026.cs), 시뮬레이션은 [PlayoffModel.Calibrated.cs](../server/src/NaverSabermetrics.Web/PlayoffModel.Calibrated.cs)에 있다. 홈 계수가 0인 기본 모델도 동일한 공식 배정을 사용한다.

## 과거 시즌 분리와 선택 절차

입력은 DB의 종료된 정규시즌 경기이며, 각 시즌의 10개 팀·720경기·팀당 144경기·상대별 16경기가 완전한지 확인한다. 경기 ID를 보존하므로 같은 날짜·팀·점수인 더블헤더도 서로 다른 경기로 유지한다. 날짜와 시즌, ID 중복, 홈·원정, 득점 자료를 검사하고 `(GameDate, GameId)`로 정렬한다. 서스펜디드 경기 때문에 ID의 날짜와 다를 수 있는 실제 `GameDate`를 사용한다.

| 구간 | 용도 | 선택 규칙 |
|---|---|---|
| 2020–2023 | 계수 추정 | 각 모델군에서 시즌별 로그손실을 동일 가중 평균하여 최소 후보 선택 |
| 2024 | 모델군 선택 | 각 모델군의 훈련 최적 후보 중 경기 로그손실이 가장 작은 모델 선택 |
| 2025 | 고정된 선택의 독립 테스트 | 계수·모델군 변경 없이 경기 지표와 진출확률 평가 |
| 2026 | 현재 서비스 | 과거 검증에서 고정한 계수 적용; 훈련·선택에 사용하지 않음 |

후보군은 기존 모델, 회귀만 적용, 회귀+홈, 회귀+상대 보정, 세 항목 모두 적용한 모델이다. k 후보는 10·20·40·80·160, 상대 보정 α 후보는 0.5·1, 양의 홈 계수 H 후보는 0.06·0.12·0.18·0.24이다. 각 항목을 쓰지 않는 모델군에서 그 계수는 0으로 둔다. 기존 모델까지 포함해 76개 조합을 훈련에서 비교했다. 전체 결과는 [선택 고정 기록](playoff-calibration/frozen-selection.json)에 보관한다.

경기 예측은 10개 팀 모두 과거 20경기 이상인 날부터 **매일 경기 시작 전의 자료**로 갱신한다. 같은 날짜의 모든 결과를 보류한 채 그날 경기를 예측한 다음, 결과를 누적한다. 더블헤더의 앞 경기 결과도 같은 날짜 예측에 넣지 않는다. 각 승패 결정 경기는 한 번만 채점한다. 무승부 경기는 이진 로그손실·Brier 계산에서 제외하되, 다음 날짜의 경기수와 득실점에는 포함한다. 그러므로 경기 지표의 목표는 무승부가 아닌 경기에서의 홈 승리 확률이다.

훈련에서 세 항목 모두 적용한 모델의 최적값은 α=0.5, k=40, H=0.06이었다. 그러나 2024년 경기 검증에서 H=0인 `shrink_opponent`가 더 낮은 손실을 보여 기본값으로 선택되었다. H=0.06은 동등한 팀의 홈 승률 약 51.50%에 해당한다. H=0의 선택은 **홈 효과가 없다는 통계적 증명**으로 해석하지 않는다.

## 경기별 검증 결과

로그손실과 Brier 점수는 낮을수록 좋다. 아래에서 **기존 모델**은 기존의 피타고리안 승률+Log5이며, 모든 경기를 50:50으로 예측하는 비교값은 별도 행이다. 2024년은 602경기, 2025년은 581경기를 평가했다.

| 모델 | α / k / H | 2024 로그손실 | 2024 Brier | 2025 로그손실 | 2025 Brier |
|---|---|---:|---:|---:|---:|
| 기존 피타고리안+Log5 | 0 / 0 / 0 | 0.703687 | 0.255102 | 0.702731 | 0.253414 |
| 회귀만 | 0 / 40 / 0 | 0.695962 | 0.251392 | 0.687355 | 0.247005 |
| 회귀+홈 | 0 / 40 / 0.06 | 0.696395 | 0.251607 | 0.687507 | 0.247071 |
| **선택: 회귀+상대 보정** | **0.5 / 40 / 0** | **0.695678** | **0.251252** | **0.686922** | **0.246816** |
| 세 항목 모두 | 0.5 / 40 / 0.06 | 0.696109 | 0.251465 | 0.687070 | 0.246882 |
| 모든 경기 50:50 | 해당 없음 | 0.693147 | 0.250000 | 0.693147 | 0.250000 |

2025년 기본 모델의 개선은 대부분 평균 회귀에서 나왔다. 회귀만 적용한 모델 대비 상대 보정의 추가 로그손실 개선은 약 0.000433으로 작다. 또한 **2024년 선택 모델은 50:50 고정 예측보다 손실이 컸다.** 기존 모델 대비 개선과 전반적인 예측력 확보를 구분해야 한다.

2025년의 `선택 모델 - 기존 모델` 차이는 로그손실 -0.015809, Brier -0.006598이다. 같은 경기의 두 예측을 짝지어 25개 **7일 단위 블록**을 5,000회 재표집한 95% 구간은 다음과 같다.

| 차이 | 95% 구간 |
|---|---|
| 로그손실 | [-0.028278, -0.004001] |
| Brier | [-0.011693, -0.001823] |

블록은 Unix 기준일로부터의 날짜 수를 7로 나눈 구간이며 ISO 주차나 월요일 시작 주간이 아니다. 이 구간은 한 시즌 내 경기 묶음의 변동을 보여준다. 시즌 간 불확실성이나 다른 연도의 일반화 성능은 측정하지 않는다. 완전한 수치와 경기수는 [독립 테스트 보고서](playoff-calibration/holdout-report.json)에 있다.

## 진출확률 검증

각 팀의 완료 경기수 중 최솟값이 20·40·60·80·100·120경기에 처음 도달한 날짜의 **경기 종료 후**를 점검 시점으로 삼는다. 그때까지의 전적과 강도로 남은 시즌을 10,000회 계산하고 실제 진출 여부에 대한 팀별 Brier 점수를 구한다. 팀별 평균을 낸 뒤 6개 점검 시점을 동일 가중 평균한다.

| 최소 경기수 | 2024 점검일 | 2025 점검일 |
|---:|---|---|
| 20 | 2024-04-18 | 2025-04-22 |
| 40 | 2024-05-14 | 2025-05-17 |
| 60 | 2024-06-07 | 2025-06-08 |
| 80 | 2024-07-04 | 2025-07-04 |
| 100 | 2024-08-03 | 2025-08-06 |
| 120 | 2024-08-31 | 2025-08-31 |

| 모델 | 2024 진출 Brier | 2025 진출 Brier |
|---|---:|---:|
| 기존 피타고리안+Log5 | 0.184570 | 0.216749 |
| 선택: 회귀+상대 보정, H=0 | 0.168207 | 0.205845 |
| 세 항목 모두, H=0.06 | 0.167258 | 0.202351 |

이 표는 날짜·경기 ID 정렬을 명시한 현재 스크립트로 다시 계산한 값이다. 정렬 보강 전후 경기별 확률과 모델 선택은 같으며, 경기 순서에 따라 난수를 배정하는 Monte Carlo 소수점 추정치는 달라질 수 있다.

H=0.06 후보는 진출확률 Brier에서 기본 모델보다 더 좋았다. 그러나 모델 선택 기준은 미리 정한 2024년 경기 로그손실이며, **2025년 진출 결과를 본 뒤 H=0.06으로 바꾸지 않았다.** 기본 모델도 모든 점검 시점에서 이기지는 않았다. 2025년의 80·100·120경기 점검에서는 기존 모델보다 진출 Brier가 컸다.

2024년 최종 승률 동률 5위는 일반 순위 정렬로 실제 진출팀을 정할 수 없다. 별도 5위 결정전에서 KT가 SSG에 4–3으로 승리하여 진출했으므로 실제 정답은 `KT=1`, `SK(SSG)=0`으로 적용했다. 결정전 기록은 정규시즌 720경기에 더하지 않았다. [KBO 5위 결정전 공지](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=10226), [KBO 게시 경기 결과](https://www.koreabaseball.com/medianews/news/breakingnews/View.aspx?bdSe=58166)

해석에는 다음 한계가 있다.

- 같은 시즌의 6개 점검은 같은 최종 진출팀을 공유하고 미래 경기도 겹친다. 60개 팀·점검 예측을 독립 표본 60개로 취급하지 않는다.
- 과거 진출 검증은 최종 완료 기록으로 남은 홈·원정 대진을 재구성한다. 기준일 당시 알 수 있었던 우천 취소·재편성의 불확실성은 반영하지 않는다.
- 향후 무승부, 부상, 로스터와 선발투수 변화, 구장별 효과, 일정 순서와 휴식일을 반영하지 않는다. 같은 한계가 비교 대상인 기존 모델에도 있다.
- 팀 강도 자체의 추정 불확실성을 시뮬레이션에서 별도로 표집하지 않는다. 특히 이른 시즌 확률은 실제보다 확신이 강할 수 있다.
- 10,000회 표집에 따른 팀별 확률의 최대 표준오차는 약 0.5%p이다. 이는 모델 가정과 데이터 오류까지 포함하는 신뢰구간이 아니다.
- 독립 테스트는 2025년 한 시즌이다. 2024년은 모델 선택에 사용했으므로 독립 테스트라고 부르지 않는다.
- DB의 누락된 종료 경기는 남은 경기처럼 보일 수 있다. 전적·대진 합계 검사는 완전한 데이터 검증을 대체하지 않는다.

## 재현 방법

`WEB` 디렉터리에서 실행한다. Python 3와 NumPy, .NET 8 SDK가 필요하다. 아래 경로는 실행자가 준비한 DB와 출력 폴더를 가리키는 예시다. 원본 DB와 개별 경기 export는 문서 증빙에 포함하지 않는다.

```powershell
python -m pip install numpy
python tools/export_playoff_games.py --db ./data/kbo.sqlite --out ./work/playoff-calibration/games.json --from-year 2020 --to-year 2026
```

export는 SQLite를 `mode=ro`로 연다. 정규시즌 종료 경기의 ID·날짜·팀·점수·구장만 내보내며 DB를 수정하지 않는다. 이후 첫 명령이 훈련과 2024년 선택을 수행하여 `frozen-selection.json`을 쓴다. 이 파일을 보존한 뒤 두 번째 명령으로 2025년을 평가한다. 별도의 `--freeze` 옵션은 없다.

```powershell
python tools/calibrate_playoffs.py --games ./work/playoff-calibration/games.json --out ./work/playoff-calibration
python tools/calibrate_playoffs.py --games ./work/playoff-calibration/games.json --out ./work/playoff-calibration --holdout
```

첫 명령은 선택 기록을 다시 쓸 수 있으므로 독립 테스트를 확인한 뒤 계수를 다시 고르는 용도로 사용하지 않는다. 테스트 실행은 입력 파일 SHA-256이 선택 때와 같은지 확인하고, 결과에 선택 파일 SHA-256을 기록한다. DB가 갱신되거나 export의 직렬화가 달라지면 입력 해시가 달라질 수 있다. 현재 증빙의 정확한 재현에는 같은 기록과 같은 입력 바이트가 필요하며, 새 데이터의 실행 결과는 별도 출력 폴더에 보관한다.

강도 수식과 공식 대진 시뮬레이션의 결정적 검증은 다음과 같다.

```powershell
dotnet run --project validation/PlayoffStrength/PlayoffStrength.Validation.csproj --configuration Release
dotnet run --project validation/PlayoffSimulation/PlayoffSimulation.Validation.csproj --configuration Release
dotnet run --project validation/PlayoffSimulation/PlayoffSimulation.Validation.csproj --configuration Release -- ./work/playoff-calibration/games.json
```

Python의 과거 시점 입력을 내보내 실제 C# 강도 계산과 비교하려면 다음 명령을 실행한다. 2020·2023·2025년, 최소 경기수 20·60·100, 기존·선택·세 항목 모델의 27개 조합을 대조한다.

```powershell
python tools/export_playoff_parity.py --games ./work/playoff-calibration/games.json --out ./work/playoff-calibration/strength-parity-fixtures.json
dotnet run --project validation/PlayoffStrength/PlayoffStrength.Validation.csproj --configuration Release -- --fixtures ./work/playoff-calibration/strength-parity-fixtures.json
```

구현 검증에서 Python과 C# 대조를 포함한 2,830개 assertion이 통과했다. 여기에는 기존 Log5 일치, 홈 효과와 H=0의 홈 배정 불변성, 회귀의 단조성, 상대 보정의 해석 가능한 예제, 팀 입력 순서 불변성, 보완 확률, 잘못된 입력 거부가 포함된다. 6개 시즌의 입력을 섞어도 날짜 정렬 후 경기별 예측은 같았다. `PlayoffSimulation`에서는 실제 2026년 경기 입력을 포함한 **253개 검사**가 통과했다. 공식 홈·원정 배정과 진출확률 합 5, 반복 결과 일치, 동률 배분, 잘못된 입력 거부 외에 설명 API의 팀 순서·평균 중심화·실제 경기수와 득실점·피타고리안 값·회귀 가중치·로그오즈를 검증했다.

최초 모델 화면은 데스크톱 1440px·모바일 390px에서 선택 계수·확률 합 5·반복 결과 일치·피타고리안 표시 유지·다른 연도 확률 미제공·JavaScript 오류와 가로 넘침 부재를 확인했다. [최초 화면·API 검증 기록](playoff-calibration/web-qa.json)

계산식 UI 추가 후에는 데스크톱 **1440·1280px**, 모바일 **390·320px**에서 다시 확인했다. 접힌 설명 열기, 네 단계 표시, 홈·원정 팀 변경, 서버 강도로 계산한 예제 확률과 화면 표시의 일치, 동일 팀 선택 방지, 제공하지 않는 연도로 바꿀 때 이전 예제 제거, 상세값 없는 응답의 안내를 검증했다. JavaScript 오류·공식 자산 요청 오류·수식과 페이지의 가로 넘침이 없었고, 데스크톱의 상단 카드 높이도 맞았다. 별도 5경기 결과 배치 회귀 검사는 1920·1440·1280·1000·390·320px에서 통과했다.

Python과 .NET은 서로 다른 난수 생성기를 사용하므로 Monte Carlo의 개별 표본까지 같은 결과를 기대하지 않는다. 두 구현의 강도와 경기 확률을 직접 비교하고, 각 시뮬레이션의 결정적 재현과 확률 범위를 별도로 검증한다.
