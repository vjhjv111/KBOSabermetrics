# 기록실 중심 UI 재구성

## 목적

기존 데이터 관리 화면을 메인 화면으로 사용하지 않고, Statiz형 기록 조회 흐름을 최상위 구조로 제공합니다.

```text
시즌기록실
통산기록실
팀기록실
연도별 상수
```

시즌·통산·팀 기록실은 다시 타자/투수로 나뉩니다. 타자 기록실은 제공된 참고 화면 순서에 맞춰 다음 하위 탭을 제공합니다.

```text
기본 / 심화 / 가치 / 확장 / 클러치 / 파워 / 팀배팅
도루 / 주루 / 타구 / 타구방향 / 투구 / 구종
```

연봉과 정밀 수비처럼 현재 원본 데이터로 확인할 수 없는 항목은 표시하지 않습니다.

## 시작 화면

`NaverRelay.Gui/Program.cs`는 `RecordRoomMainForm`을 시작합니다. 기존 `MainForm`은 삭제하지 않고 `데이터 관리` 버튼으로 여는 별도 창으로 유지합니다.

## 기록실 구분

- 시즌기록실: `PlayerByTeam`, 선택 연도 선수·팀별 기록
- 통산기록실: `PlayerCareer`, pcode 기준 전 시즌 합산
- 팀기록실: `Team`, 팀 단위 집계
- 연도별 상수: 전체 `roundCode == kbo_r` 데이터로 계산한 리그 상수와 파크 팩터

## 필터 정보 열

선수 기록실에서 필터를 적용하면 `Name` 바로 오른쪽에 `적용 조건` 열을 동적으로 삽입합니다.

예:

```text
2026 · 정규시즌 · 팀 SS · Pos 3B · 규정 50% · 최근 30일 · vs LG · 홈 · 구장 대구
```

이 열은 화면 전용이며 DB 또는 통계 DTO를 변경하지 않습니다. 팀기록실에서는 선수용 적용 조건 열을 표시하지 않습니다.

## 타자 세부 기록

기존 `BatterGameStats` 집계를 재사용하는 탭:

- 기본, 심화, 가치, 확장, 파워, 팀배팅, 도루, 주루, 투구

원시 관계형 테이블을 직접 SQL 집계하는 탭:

- 클러치: `PlateAppearances`
- 타구: `PlateAppearances.BattedBallType`
- 타구방향: `PlateAppearances.FieldDirection`
- 구종: 각 타석의 마지막 `Pitches.PitchType`

새 화면도 원본 JSON 또는 DB 내부 JSON을 다시 읽지 않습니다.

## 투수 화면

투수 참고 화면이 아직 제공되지 않았으므로 현재 데이터에서 검증된 다음 분류만 우선 유지합니다.

```text
기본 / 심화 / 가치 / 투구
```

추후 투수 참고 화면을 받으면 같은 기록실 계층 아래에서 하위 탭을 확장합니다.
