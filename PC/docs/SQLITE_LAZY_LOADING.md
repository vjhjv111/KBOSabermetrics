# SQLite 중심 지연 로딩 구조

> **이력 문서:** 현재 버전은 `docs/SQLITE_RELATIONAL_WAREHOUSE.md`의 관계형 DB 구조를 사용합니다. 아래 내용의 `NormalizedJson` 캐시/마이그레이션 설명은 이전 중간 버전 기록입니다.

## 변경 목적

이전 버전은 프로그램 시작 시 SQLite의 모든 경기 `NormalizedJson`을 역직렬화한 뒤 하나의 `_games` 목록에 보관했습니다. 5년치 데이터에서는 원본 객체, 통계 집계 결과, DataGridView 행이 중복으로 존재하면서 메모리 사용량이 수 GB까지 증가했고 UI 스레드가 오랫동안 그려지지 않는 문제가 있었습니다.

현재 버전은 SQLite를 단순 저장소가 아니라 **조회 경계**로 사용합니다.

```text
SQLite
  ├─ Games          경기 메타데이터 + 경기별 정규화 JSON
  ├─ Players        선수 검색 인덱스
  ├─ GamePlayers    경기-선수 연결 인덱스
  ├─ ParsedSources  원본 문서 지문
  └─ ComputedCache  리그/필터별 계산 결과
```

## 시작 과정

프로그램 시작 시 다음 정보만 읽습니다.

- 전체 경기 수
- 최소·최대 경기일
- 사용 가능한 연도
- 팀 코드
- 구장 목록
- 현재 화면에 필요한 경기 헤더

정규화 경기 JSON 전체를 복원하지 않습니다. 기본 연도는 DB에 있는 최신 연도이며 기본 경기 구분은 `roundCode == "kbo_r"`인 정규시즌입니다.

## 탭별 지연 로딩

### 경기 탭

`Games` 메타데이터 열만 SQL로 조회합니다. 타석·투구 객체를 만들지 않습니다.

### 클래식·세이버·WAR 탭

현재 선택한 연도, 기간, 팀, 상대, 홈/원정, 요일, 구장 조건에 해당하는 경기만 한 경기씩 읽습니다.

```text
경기 JSON 1개 역직렬화
→ 필요한 컬렉션만 남김
→ 선수별 누적값에 더함
→ 경기 객체 해제
```

완료 뒤에는 선수별 최종 행과 규정타석·규정이닝 판정에 필요한 작은 사전만 유지합니다. 같은 필터를 다시 열면 `ComputedCache`의 결과를 사용합니다.

### 리그 상수·파크 팩터 탭

화면 필터와 무관하게 전체 데이터 중 정확히 `roundCode == "kbo_r"`인 경기만 스트리밍 집계합니다. 결과는 소스 버전과 함께 계산 캐시에 저장합니다.

### 타석·투구·주루·교체·관리·진단 탭

한 번에 최대 5,000행만 표시합니다. 먼저 경기 메타데이터의 행 수를 이용해 필요한 경기 ID를 찾고 그 경기만 역직렬화합니다.

```text
◀ 이전   1 / 8 페이지   전체 37,842건   다음 ▶
```

### 선수 검색·개인 페이지

검색은 `Players` 테이블에서 수행하며 전체 경기 객체를 읽지 않습니다. 개인 페이지를 열 때만 `GamePlayers`로 연결된 해당 선수의 경기 JSON을 읽고, 그 안에서도 선택 선수와 관련된 타석·투구·최종 라인만 남깁니다.

## 취소와 UI 응답성

- 시작 시 인덱스 마이그레이션은 소량 배치로 실행됩니다.
- 필터나 탭이 바뀌면 이전 화면 조회를 취소하고 최신 요청만 유지합니다.
- `Esc` 또는 취소 버튼으로 DB 준비, 파싱, 통계 조회를 취소할 수 있습니다.
- 서비스 계층은 `ConfigureAwait(false)`를 사용하므로 대규모 역직렬화와 집계가 UI 스레드에 고정되지 않습니다.

## 메모리 특성

메모리 사용량은 전체 보유 경기 수보다 다음 항목에 좌우됩니다.

- 동시에 읽는 마이그레이션 배치: 최대 8경기 JSON
- 원본 로그 페이지: 최대 5,000행
- 현재 필터의 선수별 최종 통계 행
- 열려 있는 선수 개인 페이지의 해당 선수 경기

5년치 DB 전체를 하나의 `List<NormalizedGame>`으로 유지하지 않습니다.

## 현재 구조의 한계

정규화 원본은 여전히 경기별 JSON으로 SQLite에 저장됩니다. 따라서 처음 여는 새로운 통계 필터는 해당 범위의 경기 JSON을 한 번 스트리밍 역직렬화해야 합니다. 계산 캐시가 생성된 뒤 동일 조건은 빠르게 다시 열립니다.

향후 웹 서버 단계에서는 자주 조회하는 타석·투구·선수 최종 라인을 PostgreSQL 정규 테이블로 이관하여 SQL 집계를 확대할 수 있습니다. 현재 `DatabaseQueryModels`, `IPlayerPageService`와 Application DTO는 그 전환을 고려해 UI와 분리되어 있습니다.

## 성능 확인 방법

기존 DB를 처음 열 때:

```text
SQLite 읽기 인덱스 생성 1 / N
```

문구가 보이면 1회 마이그레이션 중입니다. 완료 후 재실행하면 이 단계는 생략됩니다.

일반 실행에서는 로그에 다음 형태가 표시됩니다.

```text
SQLite 메타데이터 로드 완료: 3,600경기 (경기 JSON은 필요할 때만 읽음)
```

작업 관리자에서 메모리가 데이터 전체 크기에 비례해 계속 상승하지 않는지, 탭을 전환한 뒤 이전 조회가 취소되는지 확인합니다.
