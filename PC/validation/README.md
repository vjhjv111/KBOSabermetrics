# 기록 정합성 검증

`dotnet run --project PC/validation/AuditRegression.csproj -- <원본 JSON 폴더>`

원본 폴더를 생략하면 낫아웃/쓰리번트 분류, 공식 정정의 멱등성·충돌·모호성 검증만 실행합니다. 폴더를 지정하면 2026년 확인된 중복·선수 교체 사례도 검증합니다.

## 수집 후 KBO 정정 대조

PC JSON 가져오기 완료 시 해당 시즌(2022년 이후)의 KBO 정규시즌 정정 목록 전체 페이지를 확인합니다. `OfficialCorrections`에 원문과 확인 시간을 보관하고 해당 경기의 기존 원본 JSON/ZIP을 다시 파싱합니다. 재수집해도 캐시된 정정이 다시 적용됩니다. DB 재생성 시에는 정정 목록을 다시 받아야 합니다.

날짜·대진·이닝·타순·선수로 타석을 유일하게 찾은 경우에만 지원하는 안타/실책/야수선택 변경을 적용합니다. 박스스코어는 현재 값이 정정 전 값일 때 변경하고, 정정 후 값이면 유지합니다. 서로 다른 값, 복수 경기/타석, 지원하지 않는 필드는 `KBO_CORRECTION_PENDING` 진단으로 남깁니다. 모든 정정을 자동 처리한다고 간주하면 안 됩니다. 실책 수 등 현재 모델이 지원하지 않는 항목은 검토가 필요합니다.

원본 중계 문장과 승리확률은 보존합니다. 기록 정정이 과거 승리확률을 다시 계산하지는 않습니다. 정정 HTTP 조회 실패는 수집 결과에 표시하며 기존 DB와 이전에 받은 정정은 보존합니다. 정정된 경기에 원본 파일이 없으면 원본 재확보가 필요합니다. 공식 수치와의 경기별 검증을 거친 DB만 웹에 배포하십시오.
